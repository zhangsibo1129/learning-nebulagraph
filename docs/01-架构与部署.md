# 01 · 架构与部署

## 1. NebulaGraph 是什么

NebulaGraph 是一款开源的**分布式图数据库**，使用 **nGQL**（NebulaGraph Query Language）作为查询语言。
它专为海量图数据（万亿级点和边）设计，支持毫秒级的多跳关系查询。

## 2. 核心架构：存算分离

NebulaGraph 由三类服务组成，各自独立部署、独立扩展：

```
┌─────────────────────────────────────────────────────────┐
│                    客户端 (Console / Python / Studio)     │
└──────────────────────────┬──────────────────────────────┘
                           │ nGQL (端口 9669)
┌──────────────────────────▼──────────────────────────────┐
│  Graph Service (graphd)  —— 查询引擎，无状态，可水平扩展   │
│  · 解析 nGQL、生成执行计划、调度执行                        │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│  Meta Service (metad)    —— 元数据管理（Raft 多副本）      │
│  · 图空间、Schema、分片分布、用户权限、集群拓扑             │
└──────────────────────────┬──────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────┐
│  Storage Service (storaged) —— 数据存储（Raft 多副本）     │
│  · 点和边按分片(Partition)分布存储，支持水平扩展            │
└─────────────────────────────────────────────────────────┘
```

**关键概念：**

| 概念 | 说明 |
|------|------|
| 图空间（Space） | 数据隔离单元，类似关系型数据库中的 database |
| 分片（Partition） | 数据水平切分的最小单位，一个 Space 的数据按 VID 哈希分布到多个 Partition |
| 副本（Replica） | 每个 Partition 有多个副本（默认 3），通过 Raft 协议保证一致性 |
| VID | 点的唯一标识（类似主键），决定数据落在哪个 Partition |

## 3. Docker Compose 部署

### 3.1 前提条件

- Docker 及 Docker Compose（本机已安装：Docker 29.7.2 / Compose v5.4.0）
- 建议内存 ≥ 8GB（3 metad + 3 storaged + 1 graphd）

### 3.2 部署配置解读

本项目的 [docker-compose.yml](../docker-compose.yml) 部署了：

- **3 个 metad**：元数据三副本，Raft 保证一致性
- **3 个 storaged**：数据三副本
- **1 个 graphd**：查询引擎（生产环境通常部署多个做负载均衡）
- **1 个 console**：命令行客户端，同时负责首次启动时把 storaged 注册进集群

关键端口：

| 服务 | 端口 | 说明 |
|------|------|------|
| graphd | 9669 | 客户端连接端口（映射到宿主机） |
| metad | 9559 | metad 间通信 |
| storaged | 9779 | storaged 间通信 |

### 3.3 启动集群

```bash
./scripts/start.sh
```

或手动执行：

```bash
docker compose up -d
# 等待 60 秒左右让服务完成初始化
docker compose ps
```

### 3.4 验证部署

```bash
# 查看所有服务状态（应为 running/healthy）
docker compose ps

# 查看集群中的 storage 节点
docker compose exec console nebula-console -addr graphd -port 9669 -u root -p nebula -e "SHOW HOSTS;"
```

`SHOW HOSTS` 输出中，3 个 storaged 的 `Status` 应为 `ONLINE`。

### 3.5 连接集群

```bash
# 方式一：进入 Console 交互模式（推荐学习使用）
./scripts/console.sh

# 方式二：单条命令执行
docker compose exec console nebula-console -addr graphd -port 9669 -u root -p nebula -e "SHOW SPACES;"
```

### 3.6 停止与清理

```bash
./scripts/stop.sh          # 停止集群（保留数据）
docker compose down        # 等价命令
rm -rf data logs           # 彻底清理数据（重新学习时使用）
```

## 4. 常见问题

| 问题 | 解决 |
|------|------|
| 容器启动后 `SHOW HOSTS` 显示 OFFLINE | 等待 1-2 分钟让 storaged 完成注册，或查看 `docker compose logs storaged0` |
| 端口 9669 被占用 | 修改 docker-compose.yml 中 graphd 的端口映射 |
| 重新部署后数据异常 | 删除 `data/` 目录后重新 `docker compose up -d`（元数据被污染时） |
| 镜像拉取慢 | 配置 Docker 镜像加速器，或从华为云镜像源手动拉取 |
| `CREATE SPACE` 后 `USE` 报 SpaceNotFound | 图空间创建是异步的，等待约 20 秒后重试 |

> **重要**：NebulaGraph 的图空间、Schema（Tag/Edge）、索引创建都是**异步**的，
> 创建后需要等待约 20 秒（2 个心跳周期）才能使用。这是分布式架构的正常行为。
